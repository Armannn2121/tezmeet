## Запуск за 1 минуту

### Вариант А — Docker (рекомендуется)

```bash
git clone https://github.com/Armannn2121/tezmeet.git
cd tezmeet
cp .env.example .env        # необязательно: впишите GEMINI_API_KEY
docker compose up --build
```

Откройте **http://localhost:8080**.

### Вариант Б — Node.js 22.18+ без Docker

```bash
npm ci
npm run build    # собрать веб-интерфейс
npm start        # http://localhost:8080
```

Режим разработки с горячей перезагрузкой: `npm run dev` → http://localhost:5173.

**Ключ API не обязателен.** Без `GEMINI_API_KEY` всё работает: смысловая близость считается через TF-IDF, первая фраза — шаблоном на трёх языках. С ключом подключаются эмбеддинги Gemini (`gemini-embedding-001`) и персонализированная первая фраза от Gemini Flash. Ключ хранится только в `.env` / переменных окружения и в репозиторий не попадает (`.gitignore`).

### Публичная ссылка за 5 минут (Render, бесплатно)

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/Armannn2121/tezmeet)

Кнопка разворачивает Docker-образ по [render.yaml](render.yaml) и выдаёт адрес вида `https://tezmeet-xxxx.onrender.com`. На бесплатном тарифе сервис засыпает после 15 минут простоя (первое открытие ~1 минута) и не хранит данные между перезапусками — для постоянной работы используйте VPS ниже.

### Деплой на сервер (VPS с Docker)

```bash
git clone https://github.com/Armannn2121/tezmeet.git && cd tezmeet
cp .env.example .env              # при желании впишите GEMINI_API_KEY
PORT=80 docker compose up -d --build
```

Сервис поднимется на `http://<IP-сервера>`. Данные участников хранятся в томе `tezmeet-data` и переживают перезапуск. Для HTTPS достаточно поставить перед ним Caddy (`reverse_proxy localhost:8080`).

## Путь «анкета → результат» (≈ 1 минута)

1. **Анкета** — цель из списка, имя, роль, опыт, стек, интересы, текст «о себе». Необязательно: с кем хотите познакомиться, свободные слоты для встреч, Telegram. Кнопка «Посмотреть на примере» заполняет анкету за вас. После отправки сразу открывается топ-5.

Внизу пять вкладок, как в мобильном мессенджере:

| Вкладка | Что внутри |
|---|---|
| **Главная** (открывается первой) | карточка мероприятия, рекомендации лентой, мои встречи, последние сообщения, знакомства |
| **Для вас** | топ-5: процент совпадения, объяснение, первая фраза, кнопки «Познакомились», «Написать», «Встреча», «Не подошло»; ниже — 2 стенда партнёров |
| **Чаты** | переписка в стиле iMessage: сообщения приходят мгновенно, «печатает…», «Доставлено / Прочитано», счётчик непрочитанных на вкладке, уведомление о новом сообщении. «Написать» у рекомендации открывает чат, где первая фраза уже вставлена в поле ввода |
| **Зал** | дашборд организатора: участники, встречи, доля «познакомились», число сообщений, спрос и предложение, карта интересов, стек, загрузка слотов |
| **Профиль** | редактирование анкеты, язык (қазақша / русский / English), статус AI, выход |

Живые участники (например, члены жюри с разных устройств) переписываются друг с другом в реальном времени. Демо-анкеты из базы тоже отвечают — автоматически, в характере своей анкеты: рекрутер рассказывает о команде, ментор предлагает помощь, предлагают время для встречи из своих свободных слотов. В их чате это подписано.

## Как работает подбор

```
Анкета ──► 1. Фильтр взаимности целей (GOAL_FIT = 0 → кандидат исключён)
           2. Скоринг каждого из ~120 кандидатов
                0.30 · совместимость целей          (hire ↔ job_seek = 1.0, mentor_seek ↔ mentor_offer = 1.0, …)
              + 0.70 · (остальные признаки) · (0.35 + 0.65 · цель)
                   0.20 роль     — нанимающий ищет именно вашу роль? смежные роли = 0.5
                   0.22 стек     — точное совпадение = 1, «семейство» (React ~ Vue) = 0.35
                   0.13 смысл    — косинус эмбеддингов Gemini или TF-IDF текста «о себе»
                   0.10 интересы — пересечение
                   0.05 опыт     — ментор старше на 3+ года; кофаундеры дополняют друг друга (техн. + бизнес)
           3. Обратная связь: «познакомились»/«не подошло» исключаются,
              похожие на отклонённых (та же роль и цель) — ×0.85,
              кроме ролей, которые вы сами ищете (одна неудача ≠ вся роль)
           4. MMR-диверсификация: пятёрка не из одной компании и не одной роли
           5. Объяснение и первая фраза: шаблон по паре целей и общим признакам
              (kk/ru/en), затем — по желанию — Gemini переписывает фразу персонально
```

Почему так:

- **Цель — главный фильтр.** Жюри проверяет «3 из 5 подходят»; самая частая ошибка нетворкинг-сервисов — показать ищущему работу таких же соискателей. Здесь это невозможно by design: несовместимые пары отсекаются до скоринга, а остальные признаки умножаются на совместимость целей.
- **Объяснение строится из тех же признаков, что и балл** — оно не может «соврать» о причине рекомендации.
- **3 секунды гарантированы без LLM.** Скоринг и шаблоны — локальные и детерминированные; LLM вызывается асинхронно и только улучшает первую фразу. Если Gemini недоступен (нет ключа, квота, 503), пользователь ничего не теряет.
- **Своя модель не обучается** — как и требуется: правила + эмбеддинги + LLM по API.
- **Кого нанимает рекрутер, понятно даже без подсказки.** Для цели «Нанять» анкета спрашивает «Кого нанимаете». Если поле пустое (например, анкета пришла через API), роли выводятся из текста «о себе» на трёх языках («нанимаем ML-инженеров» → ML-инженер) и из стека вакансии (Go + PostgreSQL → backend, PyTorch → ML/DS).

## Качество

`npm run eval` прогоняет все 120 анкет и 6 «жюри-анкет» ([scripts/eval.ts](scripts/eval.ts)):

| Метрика | Значение |
|---|---|
| Нарушений взаимности целей (кандидат с GOAL_FIT = 0 в топ-5) | **0 из 600** |
| Рекомендаций с основной совместимой целью (fit = 1.0) | **96,7 %** |
| Время подбора на сервере, p50 / max | **2,7 мс / 15 мс** |
| Объяснений длиннее 2 предложений (120 анкет × 3 языка) | **0 из 1800** |
| Время ответа API через HTTP | ≈ 7–10 мс |

`npm test` ([scripts/test-api.ts](scripts/test-api.ts)) поднимает отдельный сервер с пустой базой и проходит весь путь участника — 15 сценариев: валидация каждого поля, токен, топ-5 и взаимность целей, три языка, «не подошло» → пересчёт → отмена, «познакомились» → знакомства, два живых участника находят друг друга, приватность Telegram, встречи (общий слот, стол, дубликаты, кто может отменять), чат (мгновенная доставка через поток событий, непрочитанные, «прочитано», чужую переписку не прочитать), редактирование анкеты, дашборд, защита статики, ответы демо-анкет («прочитано», «печатает…», один ответ на серию сообщений, на языке собеседника), сохранность данных после перезапуска.

## Данные

- **120 анкет** ([JSON](data/profiles.json), [CSV](data/profiles.csv)) созданы скриптом [scripts/generate-profiles.ts](scripts/generate-profiles.ts) (детерминированно, `npm run seed`). Имена — случайные сочетания имён и фамилий, компании вымышлены, тексты «о себе» — шаблоны на трёх языках (ru 75, kk 23, en 22). Реальные профили LinkedIn/Telegram **не использовались и не парсились**.
- Распределение целей сбалансировано под живой митап: нанимают 20, ищут работу 28, ищут ментора 20, менторы 16, ищут кофаундера 16, обмен опытом 20; 19 ролей.
- **9 стендов партнёров** — [data/booths.json](data/booths.json), вымышленные компании.
- Анкеты, которые вводят участники, сохраняются в `var/state.json` (в Docker — том `tezmeet-data`) и сразу становятся кандидатами для других участников.

## Архитектура

```
web/          React 19 + Vite — интерфейс в стиле iOS (HIG): large titles, inset grouped lists,
              bottom sheets, segmented control, tab bar с размытием, светлая/тёмная тема
server/       Node.js без внешних зависимостей (TypeScript исполняется напрямую, Node ≥ 22.18)
  match.ts      скоринг, фильтр целей, обратная связь, MMR, стенды
  explain.ts    объяснения и первые фразы (kk/ru/en)
  text.ts       TF-IDF, сходство стека по «семействам» технологий
  embed.ts      эмбеддинги Gemini + кэш на диске (var/embeddings.json)
  llm.ts        персональная первая фраза (Gemini, structured output, fallback по моделям)
  autoreply.ts  ответы демо-анкет в их характере (kk/ru/en), «печатает…», один ответ на серию сообщений
  store.ts      анкеты, обратная связь, встречи, сообщения (JSON-файл с атомарной записью)
shared/       справочники (цели, роли, стек, интересы, слоты) и типы — общие для сервера и UI
data/         синтетические анкеты (JSON + CSV), стенды партнёров
scripts/      генератор анкет, оценка качества, dev-режим
```

### API

| Метод | Путь | Что делает |
|---|---|---|
Анкета создаётся без регистрации: `POST /api/profiles` возвращает анкету и секретный токен, браузер хранит его и отправляет как `Authorization: Bearer …`. Все действия от имени участника — только под `/api/me` и только с токеном (id участников видны другим, токен — нет).

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/meta` | справочники, событие, статус AI |
| POST | `/api/profiles` | создать анкету → `{ profile, token }` |
| GET | `/api/profiles/:id` | публичная карточка (без Telegram) |
| GET / PUT | `/api/me` | своя анкета / изменить её |
| GET | `/api/me/recommendations?lang=kk` | топ-5 + стенды + время подбора |
| POST | `/api/me/icebreakers` | персональные первые фразы от Gemini |
| POST | `/api/me/feedback` | `met` / `skip` / `undo` → пересчитанный топ-5 |
| GET | `/api/me/contacts` | с кем познакомились |
| GET | `/api/me/free-slots?targetId=` | общие свободные слоты или уже назначенная встреча |
| GET / POST / DELETE | `/api/me/meetings[/:id]` | расписание 1:1: слот, стол, отмена |
| GET | `/api/me/chats` | список переписок + число непрочитанных |
| GET / POST | `/api/me/chats/:id` | открыть переписку (отмечает прочитанным) / отправить сообщение |
| GET | `/api/me/events` | поток событий (SSE): новые сообщения и «прочитано» в реальном времени |
| GET | `/api/dashboard` | агрегаты для дашборда организатора |
| GET | `/api/health` | проверка живости |

### Безопасность и приватность

- Ключ API — только в окружении сервера; браузер его не видит.
- Текст анкет передаётся в LLM как данные, не как инструкции; ответ ограничен JSON-схемой и длиной.
- Действия от имени участника — только с его токеном; в базе хранится лишь SHA-256 токена.
- Валидация всех полей, лимит размера тела запроса, rate limit по участнику и маршруту (весь зал может сидеть за одним Wi-Fi), атомарная запись файла.
- Telegram участника видят только те, кого он сам отметил «Познакомились».
